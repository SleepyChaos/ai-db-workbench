# MVP 范围

## 已确认的定位

目标用户为后端开发、运维和个人开发者。产品用于便利数据库操作，并提供原生脚本编辑、结构查看、批量执行和执行记录等工程化体验。

面向运营等业务人员的报表助手、业务指标解释与 BI 看板不在 MVP 内。用户仍可执行聚合查询并导出结果，但产品不承诺理解企业业务口径。

## 页面职责

### AI 对话页

- 选择连接和操作对象，引用工作台当前上下文。
- 上传文件，预览解析结果，提出导入、查询、创建和修改需求。
- 查看 AI 生成的操作步骤、目标对象、原生语句及恢复边界。
- 修改生成的语句；确认写入方案后执行。
- 展示查询结果、批量任务进度、逐步结果和错误解释。
- 支持把生成的脚本送入数据库工作台继续编辑执行。

### 数据库工作台

- 创建、编辑、测试和切换连接；显示可达性与连接错误。
- 浏览数据库对象及其实际结构、索引或元数据。
- 查看真实内容，提供该数据库适用的筛选、分页或游标浏览。
- 提供原生脚本、命令或表达式编辑及执行入口。
- 提供数据修改、结果导出和执行历史等常规功能。
- 按数据模型展示内容：表格、JSON 文档、Key 值、节点与关系等。

工作台不强制用户经由 AI 才能操作。它展示实时读取的数据或明确标记的缓存，不以 AI 的文字回复作为执行成功依据。

## 共同能力边界

1. **连接与浏览**：九种数据库都支持真实连接、元数据和内容查看。
2. **AI 基本操作**：理解目标数据库模型，生成适配的原生操作；不能把所有数据库抽象成 SQL 表。
3. **文件导入**：预览文件、配置映射、创建必要对象、批量写入、展示结果。各库支持适合其模型的格式，不要求所有格式互相通用。
4. **原生执行**：可编辑、执行并保存数据库原生脚本或操作描述。首版不是任意 Python、Shell、JavaScript 代码运行平台。
5. **记录与恢复**：记录目标连接、对象、实际执行内容、步骤状态、影响数量和错误。按操作与数据库能力标明恢复方式。

AI 读取必要的元数据和用户选择的样本。连接凭据不进入模型上下文；向模型发送哪些样本需要在产品中可见。

## 回滚、补偿和撤销

- **事务回滚**：仅适用于目标引擎与操作支持事务、且尚未提交的操作。
- **补偿操作**：通过新的操作抵消此前成功步骤，如清理本任务新建的对象。补偿不是原子回滚，也可能失败。
- **提交后撤销**：仅覆盖拥有必要恢复信息、且能检查后续变更冲突的受支持场景。
- **不支持恢复**：执行前明确提示，记录中仍可查询执行过程；不承诺任意删表、删字段或覆盖数据后的恢复。

MySQL 的 DDL 不能通过简单包裹事务获得整批回滚。MongoDB 多文档事务需要支持的部署形态。连接检测和执行计划必须考虑这些条件。

批量执行应显示每步成功、失败、未执行或结果未知。网络中断导致结果未知时，不自动重试可能重复写入的步骤；先核验数据库状态。

AI 生成写入方案后，由用户确认具体计划再执行。手写操作走相同执行记录和能力检查机制，具体确认交互在 UI 设计阶段确定。

## 不包含

- 面向业务人员的报表助手、BI 看板、定时报告。
- 跨数据库联查、跨引擎迁移、持续数据同步。
- 集群运维、自动调优、完整备份恢复平台。
- 多人协作、组织权限、企业审批。
- 通用代码执行平台、任意操作的一键无损撤销。
- RDF、原生 XML、对象数据库等专门类别的额外接入。
