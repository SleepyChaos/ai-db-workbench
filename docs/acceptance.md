# MVP 验收与交付顺序

## 全局完成标准

九种数据库全部通过下列共同验收，并完成各自代表场景，才算本次 MVP 完成。接入顺序不改变首版范围。

1. 可创建真实连接，检测错误凭据、网络错误，并显示明确错误。
2. 可浏览真实对象与数据；查询结果支持有界读取，不因大结果集卡死页面。
3. 可经原生操作入口执行代表查询与写入，并查看结果和执行记录。
4. 可通过 AI 生成适配当前连接的操作，查看原生内容并确认写入。
5. 可上传适配文件，预览映射，创建必要对象并完成导入。
6. 写入后工作台重新读取数据库，显示真实结果。
7. 批量失败时显示成功、失败、未执行和结果未知的步骤，不把部分成功标成全部成功。
8. 可明确判断恢复方式；不支持的恢复操作不能显示成可用的一键回滚。
9. 查询结果可按模型导出为 CSV 或 JSON；明确导出的是当前结果、选定范围还是完整查询结果。

## 逐库代表场景

| 数据库 | 最小验收场景 |
| --- | --- |
| MySQL | 上传两份 CSV，AI 生成两张表和导入方案；执行后查看字段和行数据；查询关联结果；新增字段；模拟中途失败并验证清理方案只针对本任务创建的对象 |
| MongoDB | 导入含嵌套字段的 JSONL；查看文档；执行过滤和聚合；批量更新一个字段；区分抽样概览与真实校验规则 |
| Redis | 导入 Key/Value 数据；浏览值与 TTL；读写 Hash；执行一批命令并展示逐项结果，验证无虚假的失败回滚承诺 |
| Cassandra | 明确分区键后建表导入；按键查询和修改；对不符合支持范围的查询给出明确反馈 |
| Neo4j | 导入节点与关系文件；查看小规模关系图；执行路径查询；修改节点属性 |
| InfluxDB | 映射时间戳、标签和数值字段后导入；按时间窗口查询和聚合；查看记录及趋势 |
| Elasticsearch | 创建 Mapping 后批量导入文档；执行全文搜索；展示每项导入错误并核验可检索内容 |
| ClickHouse | 指定排序键后建表导入；执行分组聚合；查看结构与数据；对于异步变更明确展示进度或状态 |
| Milvus | 导入已有数值向量和元数据；验证维度；执行向量检索与标量过滤；展示匹配项、度量和得分 |

## 恢复验收

- 事务支持的测试场景：在提交前注入失败，验证应回滚的写入没有保留。
- 补偿场景：记录本次新建对象；生成清理计划；核验后执行，避免删除同名既有对象。
- 后续变更冲突：补偿前对象已被修改或新增数据时，停止自动补偿并说明原因。
- 网络断开：无法确认提交结果时标记结果未知，核验前不盲目重放写入。
- 不支持恢复的场景：执行前展示边界，执行后保留日志，不展示错误的撤销按钮。

## 建议交付顺序

1. 基于 Rust + Vue + Pi + Docker Compose 固定依赖、数据库版本与模型 API。
2. 连接管理、执行结果协议、历史记录、工作台基础布局。
3. MySQL 实现完整垂直流程，验证文件导入与 AI 执行机制。
4. MongoDB、Redis 验证非表格模型和不同命令形式。
5. Cassandra、Neo4j、InfluxDB、Elasticsearch、ClickHouse、Milvus 完成各自代表流程。
6. 在九种数据库真实环境下完成回归、错误与恢复边界验证。

开发环境通过 Compose profiles 按需启动数据库，避免九种服务同时运行成为本地开发的前提。应用核心为 Rust app 和 Pi agent 两个服务，部署细节见 [Pi 接入与部署设计](pi-and-deployment.md)。

## Pi 与部署验收

- Pi 接收到对话并流式返回事件；实际调用数据库工具后能展示 Rust 返回的真实结果。
- 未确认的写入计划不能执行；计划内容修改后旧确认失效；重复确认不会重复启动同一任务。
- 停止 Pi 生成不等于数据库已停止执行；取消与结果未知状态可以在 UI 中区分。
- app 与 agent 使用 Compose 服务名通信；浏览器只访问 app 的 Web 端口。
- agent 不发布宿主机端口，但能访问配置的模型 API。
- 重建容器后，所需连接配置、对话和执行记录从持久化卷恢复。
- 发布产物包含本项目许可证及随附第三方组件所需的许可证与版权声明。
