# 技术设计约束与待定项

本文件区分已确认的技术方向、工程选择与尚未确定的实现细节。

## 已确认的技术方向

- 后端使用 Rust；前端使用 Vue，保持简单的 Web 形态。
- Agent 直接接入 Mario Zechner 创建的 Pi（原 badlogic/pi-mono，当前 earendil-works/pi）。
- 中间连接层保持轻薄；使用 Docker Compose 项目网络进行服务间通信。

工程选择：Rust 采用 Axum + Tokio；前端采用 Vue 3 + Vite + TypeScript；Pi 使用 Node.js 运行其 TypeScript 库，通过内部 HTTP 和事件流连接 Rust。前端构建后由 Rust 提供静态文件，不为生产部署额外增加前端运行服务。

具体职责、内部接口和网络边界见 [Pi 接入与部署设计](pi-and-deployment.md)。

## 设计约束

- AI 对话与工作台共用连接上下文和执行服务，避免两套执行逻辑不一致。
- 每种数据库提供适配器，负责连接检测、元数据、内容浏览、原生执行、导入和能力描述。
- 统一返回连接、目标对象、原生请求、结果、影响数量、耗时、错误、步骤状态与恢复信息。
- 保留数据库自身的对象与数据模型，不强制所有对象都变成关系表。
- 能力描述需考虑数据库类型、具体版本、部署形态及当前权限。
- AI 生成计划，执行服务验证并执行；模型本身不持有连接凭据。
- 历史记录保存实际执行内容，用户修改生成脚本后，需要重新验证计划与恢复边界。
- 长任务与批量操作拥有任务 ID 和逐步状态。取消、超时、断连与执行失败是不同状态。
- 根据操作语义核验结果；请求被接受、任务完成、读查询可见不能混为一谈。

## 待定项

| 决策 | 当前状态 |
| --- | --- |
| 后端语言与框架 | Rust + Axum + Tokio；依赖固定在 Cargo.lock |
| 前端框架、编辑器和组件库 | Vue 3 + Vite + TypeScript；编辑器和组件库按实际需要选择 |
| 运行与部署形态 | Web 应用 + Docker Compose；默认本机访问，项目网络内部互联 |
| Agent 框架 | Pi 1.4.0：pi-agent-core + pi-ai；Node.js 24+ 薄服务 |
| 模型提供方、模型 API 和配置方式 | 支持 OpenAI 兼容接口、OpenAI、Anthropic；通过 .env 配置，具体提供方由使用者选择 |
| 各数据库固定版本与驱动 | 待定，尤其需明确 InfluxDB 版本及查询语言 |
| 本地连接信息、凭据和历史记录存储方式 | 成功对话保存为 JSON 文件并挂载卷；数据库连接凭据存储留待连接管理阶段 |
| 文件大小、批次大小、查询行数及超时上限 | 待定，必须可明确展示 |
| 数据网格编辑方式、写入确认交互 | 待 UI 设计确定 |
| 开源许可证 | 本项目 MIT；Pi 原始 MIT 文本与版权见第三方声明；安装依赖后补齐其他声明 |
