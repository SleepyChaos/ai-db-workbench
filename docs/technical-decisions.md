# 技术设计约束与待定项

本文件区分产品已确认的边界与尚未确定的实现选择，不代表技术栈已经选定。

## 设计约束

- AI 对话与工作台共用连接上下文和执行服务，避免两套执行逻辑不一致。
- 每种数据库提供适配器，负责连接检测、元数据、内容浏览、原生执行、导入和能力描述。
- 统一返回连接、目标对象、原生请求、结果、影响数量、耗时、错误、步骤状态与恢复信息。
- 保留数据库自身的对象与数据模型，不强制所有对象都变成关系表。
- 能力描述需考虑数据库类型、具体版本、部署形态及当前权限。
- AI 生成计划，执行服务验证并执行；模型本身不持有连接凭据。
- 历史记录保存实际执行内容，用户修改生成脚本后，需要重新验证计划与恢复边界。
- 长任务与批量操作拥有任务 ID 和逐步状态。取消、超时、断连与执行失败是不同状态。
- 根据操作语义核验结果；请求被接受、任务完成、读查询可见不能混为一谈。

## 待定项

| 决策 | 当前状态 |
| --- | --- |
| 后端语言与框架 | 待用户技术偏好确定 |
| 前端框架、编辑器和组件库 | 待定 |
| 本地 Web、桌面应用或其他运行形态 | 待定；本地 Web 只是前期建议 |
| 模型提供方、模型 API 和配置方式 | 待定 |
| 各数据库固定版本与驱动 | 待定，尤其需明确 InfluxDB 版本及查询语言 |
| 本地连接信息、凭据和历史记录存储方式 | 待定 |
| 文件大小、批次大小、查询行数及超时上限 | 待定，必须可明确展示 |
| 数据网格编辑方式、写入确认交互 | 待 UI 设计确定 |
| 开源许可证 | 待项目所有者选择 |

## 后续仓库结构

确定技术栈后再创建应用源码与依赖配置。建议按前端、后端、数据库适配器、集成测试、开发环境和文档划分职责；当前不创建空实现或宣称已有运行能力。
